### What the scratch runs showed (V, `p22/a2/refuse.log`, `p22/a2/remedies.log`)

- **Identity.** With `GIT_CONFIG_GLOBAL=/dev/null` and no system
  config, git 2.56.0 on this machine did **not** print 'Please tell
  me who you are'. It guessed an identity from the login name and the
  host name, committed, and printed 'Your name and email address were
  configured automatically...'. The refusal ('Author identity
  unknown / *** Please tell me who you are.') appeared only with
  `-c user.useConfigOnly=true`, which stands in for a host where git
  cannot guess. The preflight therefore describes both outcomes and
  calls the silent guess the worse one. This differs from the
  model-book report (M2), which records the refusal under
  `GIT_CONFIG_GLOBAL=/dev/null`; the outcome depends on the host name.
- `git init` without `-b` gives `master` and the Git 3.0 hint (V).
- `error: src refspec main does not match any` reproduced both for a
  `master` branch and for no commit yet (V). `git branch -m main`
  then push works (V).
- `! [rejected] main -> main (fetch first)` plus the 'Updates were
  rejected because the remote contains work that you do not have
  locally.' hint (V). The follow-up `git pull` with no pull config
  stops with `fatal: Need to specify how to reconcile divergent
  branches.` (V); `git pull --no-rebase` merges and the push succeeds
  (V). I folded this into the 'fetch first' row to stay at eight rows.
- A forge-made README commit gives 'fetch first' on push and then
  `fatal: refusing to merge unrelated histories` on merge or pull
  (V); `git pull --no-rebase --allow-unrelated-histories origin main`
  joins them (V).
- Detached HEAD advice text and `HEAD detached at 56095c2` (V).
- Merge conflict messages and markers (V).
- `git commit --amend --reset-author` is git's own suggestion and
  fixes the guessed identity (V).
- `git config --global --list` prints `init.defaultbranch=main` in
  lowercase (V), as the preflight says.
- Large-file remedy: `git rm --cached` + `git commit --amend` refuses
  when the large file was the commit's only change ('would make it
  empty'), V; hence the '(or `git reset HEAD~1` ...)' clause, which
  is inferred from the chapter's own reset description, not run.
- `git check-ignore -v` prints nothing (exit 1) for a path no rule
  ignores (V), as the cheat-sheet row says.
